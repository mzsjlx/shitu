原始数据有752条带 highway 的 way。旧 JSON 只有406个带标签节点，完整 XML 恢复后共12554个原节点，本次752条 way 未发现缺失节点。保守模型剔除 foot 禁止32条、无步行例外的受限 access 10条、室内/非零 level 13条、其他类别1条，再移除146条桥隧或非零 layer 路段，保留550条way、3036个图节点、16个弱连通分量。

源查询矩形是取数范围，不是资料完整范围。返回的 way 可能延伸出查询框，边界外后续连接未必完整；即便所有返回 way 坐标齐全，也不能声称找到了重庆实际全局最短路线。当前终点离源查询南边界很近，保留局部试算的明确范围。

## 图算法规则建议

1. 使用原始 way.nodes 和节点 ID；只在共享原节点处连接。不得因线段二维相交、相近、投影交叉就连通，尤其是桥、隧、地面跨层处。
2. 保守第一版可只做地面道路图，桥、隧和非零层排除。以后支持桥隧时保留原有共享端节点及坡道、楼梯等显式连接，不补造跨层连接。
3. 解析 foot、access、foot:conditional、access:conditional 及节点 barrier/access；显式 foot 许可可以覆盖一般 access 禁止，foot no/private 则拒绝。customers、permit、delivery 等不能当作公共步行许可。
4. 普通机动车 oneway 不直接套给步行；步行方向使用 oneway:foot、foot:forward、foot:backward。不要把机动车禁左转关系直接施加给行人；需识别适用模式，本样板也未触及该关系。
5. 不复用视觉分隔线或经过裁切/简化的瓦片作为道路拓扑。保留原节点、完整tags、way来源及距离计算方式。
6. 若今后缺少节点，不跨缺口补线；可整条拒绝，或明确拆成不跨缺失点的完整片段。不可通过最近点自动把不连通分量接起来。
7. 门店入口应单独核实到道路的可达连接。当前两条候选保持 routeEligible=false；技术样板以道路节点为端点，与想去清单及门店卡片隔离。
8. 暂不提供到店距离、预计步行分钟数、无台阶保证或无障碍路线。后续应检查 sidewalk/crossing、台阶、坡度、门禁、楼层及现场入口；现有粗 DEM 不足以计算真实爬升或桥面高差。
