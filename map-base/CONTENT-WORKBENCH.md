## 当前可以做什么

左侧选择超级李板凳面或赵二火锅，中间分别填写地点来源、具体分店、门店入口、图片用途、视频用途、入口到道路六项。地点原坐标只读，不能直接当门口。材料库可增加标题、原页 HTTPS 链接或本地资料位置文字、日期与定位说明；再回到对应检查项引用材料，填写判断依据。外链和本地位置不会被自动读取、下载或执行。

右侧即时列出缺项。草稿结论“认为有依据”需有材料和说明；字段齐全时仅显示“可提交复核”。程序只能检查结构，不能判断文字、坐标或授权材料属实，也不会修改公众候选状态。当前两家仍未核实入口、没有到店导航，配图仍是注明用途的 AI 菜品示意。

缓存线索弹窗展示64条餐饮相关来源记录，只读，不能通过导入扩充编辑目录。本轮原 XML 审查有22个显式入口，其中8个在当前地面道路图内，但没有材料把它们明确关联到餐饮点，合格配对为0。不是“整个重庆不存在入口数据”。复现结果在 ../output/entrance-candidate-audit.json 与 .md。

## 从视频简介整理文字线索

在“材料库”点击“整理视频简介”，填写公开原页的HTTPS链接、材料标题、读取日期；作者与发布日期未知可留空。粘贴实际读到的作者简介后预览，程序只按字面找出地址/门牌、时间点与现有门店名称，不读取链接，不下载视频、封面或照片，也不判断原文是否属实。

逐行勾选要保留的文字，再手动选归入哪家现有候选，点击“保存为一份材料”。摘录保留原文行号与先后顺序，未勾选的行不进入材料；全篇原文不会另存。名称文字命中不会自动选择候选，相邻两行也不会被自动认定属于同一家店。来源/正文修改后须重新预览；此入口不能创建新的公众门店。

保存只增加材料库记录，六项核实结论、材料引用、分店/入口/媒体用途均保持原值。随后回到“核实项目”选择引用、写判断依据，材料完整度仍不等于事实或授权确认。与现有草稿共用自动本地保存及JSON导出；存储不可用时仅保留本页内存并显示未保存。

一次正文最多12000字，最多识别40行，每行最多400字；所选摘录含说明最多2000字。超过时请分段或减少选择，不自动截断原文。每店仍最多50份材料；重复原页与相同线索会阻断。取消/关闭不会写入草稿。文字识别没有语义理解，不把时间点当作已验证的播放位置、地址当作已确认分店或入口。

2026-10-25检查：CONTENT-INTAKE-MODEL-QA.json的23项模型检查与CONTENT-INTAKE-UI-QA.json的35项浏览器检查通过，含显式选择/归属、预览失效、结论与原稿保留、导出、额度失败、文本安全、四种尺寸及错误可见性。测试为隔离合成材料，未写入用户浏览器或作为真实门店证据。

## 保存与备份

- 编辑自动保存在当前浏览器、当前地址的独立键 foodcity:content-review:chongqing:v1，不上传服务器，也不影响公众想去清单。换浏览器或端口后不是同一份存储。
- “导出草稿”下载 JSON，包含自己填写的材料与备注；建议在清理浏览器或换设备前导出。图片/视频附件本体不包含在 JSON 中，本地资料位置只是文字线索。
- “导入草稿”先整体检查再预览，点击替换才写入；取消或校验失败保留原稿。只接受当前两家候选，文件最大512 KiB；缺少的候选恢复初始草稿，不与旧稿自动合并。旧基础版本保留但显示版本不一致，不能达到资料就绪。
- 导入或恢复初始资料后可以撤销，继续编辑会结束这次撤销机会。存储额度不可用时保留当前内存输入并显示“尚未保存”，可先导出；重新载入会失去未保存输入。损坏的旧稿不会被编辑自动覆盖。

初始材料的日期不是同一天：地图记录来自10月19日缓存，2020历史作者页于10月22日读取，项目示意图资料于10月23日整理。10月25日加入较新的2026原作者视频与地址简介材料，读取日期单独记录为10月25日，旧材料日期没有统一改写。来源见 ../CREATOR-GUIDES-SOURCES.md；仍不能把工具更新日期当作门店或入口核实日。

## 工程与检查

界面在 src/content-review.html、content-review.js、content-review.css，数据规则在 src/content-review-model.js；目录由 scripts/prepare-content-review.mjs 生成。规则正文在 ../CONTENT-REVIEW-RULES.md。

~~~powershell
node scripts/prepare-content-review.mjs
node scripts/review-content-model.mjs
npm.cmd run build
~~~

修改候选或道路源资料后，先更新来源审查，再重新生成目录与构建；版本不一致的旧草稿须重新复核。检查报告为 CONTENT-MODEL-QA.json（85项）、CONTENT-UI-QA.json（33项）和 CONTENT-FAILURE-QA.json（4项），均通过。界面检查使用浏览器模拟；合成完整资料不是现实门店证据。

当前是仅供本机使用的资料工具，尚无服务端存储、多人账号、权限或发布流程。后续取得具体分店、入口、可通行连接及可用素材后，再单独复核并更改公众内容。
